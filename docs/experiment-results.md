### ตัวชี้วัด

| ตัวชี้วัด | ความหมาย |
|---|---|
| **CER** (Character Error Rate) | (S + D + I) ÷ N ยิ่งต่ำยิ่งแม่น เช่น เฉลย 10 ตัวอักษร ผิด 2 ตัว = 20% |
| **S** Substitution | ตัวอักษรที่ถูกแทนด้วยตัวอื่น (ฟังผิด) |
| **D** Deletion | ตัวอักษรที่ตกหล่น (เสียงหาย) |
| **I** Insertion | ตัวอักษรที่เกินมา (แต่งเพิ่ม/หลอน) |
| **N** | จำนวนตัวอักษรของเฉลย (L1/L2 = 9,490) |
| **WER** | แบบเดียวกับ CER แต่นับเป็นคำ (ใช้กับอังกฤษ) |
| **ตัวอักษรในช่วงกับดัก** | จำนวนตัวอักษรที่ Whisper สร้างใน segment ที่ทับช่วงกับดัก > 50% (เฉพาะ L1) ยิ่งสูงยิ่งหลอนในที่เงียบ |
| **ประโยคที่เริ่ม ±2 วินาที** | % ของประโยคที่มี segment เริ่มห่างจากจุดเริ่มจริงไม่เกิน 2 วินาที (วัดความละเอียดของ timestamp) |
| **VAD** (Voice Activity Detection) | ตัวตรวจว่าช่วงไหนมีเสียงพูด (ใช้ Silero) |
| **การ normalize** | ตัวพิมพ์เล็ก ตัดช่องว่างและวรรคตอน **เก็บสระ/วรรณยุกต์ไทย** |

### E3: ทดสอบ 3 ภาษา (เสียงของผู้ใช้เอง)

**คำถาม:** C3 (Typhoon) และ C4 (turbo) ถอดภาษาอื่นได้ไหม และตรวจจับภาษาเองได้ไหม (`-l auto`)

| ภาษา | C3 Typhoon (ตั้งภาษาถูก) | C4 turbo (ตั้งภาษาถูก) | ภาษาที่ตรวจพบ (`auto`) |
|---|---|---|---|
| ไทย (232 ตัวอักษร) | CER 23.3% (S15 D1 I38) | **CER 8.2%** (S14 D1 I4) | ทั้งคู่ `th` ถูก |
| อังกฤษ (30 คำ) | **WER 100%** | **WER 0%** | turbo `en` ถูก / Typhoon `th` ผิด |
| จีน (61 ตัวอักษร) | **ใช้ไม่ได้** (CER 352%) | **CER 9.8%** (S2 I4) | turbo `zh` ถูก / Typhoon `th` ผิด |

**ข้อสรุป:**
- Typhoon ใช้ได้เฉพาะภาษาไทย แม้ตั้ง `-l en`/`-l zh` ก็ยังเขียนเป็นอักษรไทย (อังกฤษกลายเป็นประโยคไทยไร้ความหมาย, จีนถูกสะกดเป็นพินอินแบบไทย เช่น "วัวซิ่งจัง" แทน 我姓张)
- turbo ถอดได้ทั้งสามภาษาและตรวจภาษาถูกทุกครั้ง
- ภาษาไทยรอบนี้ turbo ชนะ ต่างจาก E2 เพราะ Typhoon เขียนตัวเลขเป็นคำ ("ยี่สิบสองขีดเจ็ด") ขณะที่เฉลยเป็น 22-7 (I = 38) และมีตัวอักษรหาย ไม่ใช่ความผิดเรื่องเสียงล้วนๆ
- turbo ต่อท้ายคำหลอน `感谢观看` ("ขอบคุณที่รับชม") ในไฟล์จีน ซึ่งไม่มีในเสียง
**ข้อจำกัด:** ตัวอย่างเล็กมาก (จีนผิด 6 ตัวจาก 61) คนพูดคนเดียว ครั้งเดียว
**สไลด์:** ตาราง 3 ภาษา + ตัวอย่างข้อความที่ถอดได้ (ภาพ "Typhoon ถอดอังกฤษเป็นไทย" น่าสนใจ)

### E4: VAD กับเสียงพูดต่อเนื่อง (ข่าวช่อง 9, 243.5 วินาที)

**คำถาม:** VAD ตัดท่อนได้ตามที่ตั้งใจไหม
**ผล:**
- VAD ดิบได้ 40 ช่วง แต่มีช่วงพูดยาว **65.9 และ 47.4 วินาที** (ผู้ประกาศอ่านต่อเนื่อง ไม่มีช่วงเงียบถึง 100 ms)
- ตัวเลือก `-vmsd` (ตัดช่วงยาวอัตโนมัติ) **ไม่มีผลเลย** ในเครื่องมือนี้ ปรับ `-vsd`/`-vt` ก็ไม่แยกช่วง 66 วินาที
- วิธีแก้: วัดพลังงานเสียงทุก 10 ms ตัดที่จุดเบาที่สุดในช่วงที่ยาวเกิน 25 วินาที ได้ **5 จุดตัด** ที่ 30.3, 51.5, 103.8, 124.5, 134.5 วินาที (พลังงาน 3–7% ของค่ากลาง)
- ผลสุดท้าย: **13 ท่อน** ยาวสุด 24.4 วินาที ทิ้งช่วงเงียบ 5.6 วินาที (2.3% ของไฟล์)
**ที่ยังไม่ได้พิสูจน์:** ว่าจุดตัดไม่ตกกลางคำ (ต้องฟังตรวจ ใช้หน้า `data/vad-test/out/index.html`)
**สไลด์:** ภาพรูปคลื่นเสียงพร้อมเส้นตัด (ควรทำกราฟจากไฟล์ `full.wav`) และแผนผัง pipeline

### E5: การปรับค่า Whisper กับเลคเชอร์ 42 นาที (ไม่มีเฉลย ดูอาการวนซ้ำ)

**ปัญหา:** ผลถอดเสียงมีวลีวนซ้ำเป็นร้อยรอบ (เช่น "คอร์ดิชั่นนี้คือ…", "0.1 + 0.1 + …") และ segment ซ้ำ

| แบบ | segment ดิบ | ตัวอักษรดิบ | segment วนซ้ำ (ดิบ) | หลังตัวล้าง |
|---|---|---|---|---|
| ค่าเดิม (`-mc 0` + VAD) | 560 | 25,617 | 6 | 556 segment / 24,292 ตัวอักษร / วนซ้ำ **0** |
| F1: ปิด fallback `-nf` + `-sns` + VAD ตัดทุก 15 วินาที | 588 | 25,409 | **13** (แย่กว่า) | 580 / 23,290 / 0 |
| F2: `--prompt` ศัพท์เฉพาะ + `-mc 64` | 926 | 44,264 (ขยะวนซ้ำ) | 7 | 63 / 4,178 (**ข้อความหาย 83%**) |

**ข้อสรุป:** ไม่มีการตั้งค่า Whisper ตัวไหนดีกว่าค่าเดิม สิ่งที่ได้ผลคือ **ตัวล้างหลังถอดเสียง** (`collapseRepeats` ตัดวลีที่ซ้ำ ≥4 ครั้ง + รวม segment ที่เริ่มพร้อมกัน) ลดการวนซ้ำเหลือ 0 โดยไม่เสียเนื้อหา ส่วน `--prompt` ใช้ไม่ได้ผลกับ `-mc 0` และพังเมื่อเปิด context
**ความเร็วพื้นฐาน:** turbo ถอดเลคเชอร์ 42 นาทีใน 326 วินาที (≈7.7 เท่าของเวลาจริง)
**สไลด์:** ก่อน/หลังตัวล้าง ยกตัวอย่างข้อความวนซ้ำจริง (การปรับปรุงที่ทำเอง ตรงข้อ 3 ของเกณฑ์วิชา)

### E6: ขั้นสรุปด้วย LLM (Typhoon 4B Q4_K_M, llama.cpp)

| หัวข้อ | ผลที่วัดได้ |
|---|---|
| โมเดล | Typhoon 2.5 Qwen3 4B GGUF Q4_K_M (2.5 GB) รันบน GPU ทั้งหมด |
| VRAM ตามขนาด context (KV cache q8_0) | ctx 8,192 = **3,567 MiB**, ctx 12,288 = 3,813 MiB, ctx 4,096 ใช้ไม่ได้ (ช่วง 10 นาทีไทยมี ~5,564 token) |
| ความเร็ว | อ่าน prompt ~1,117 token/วินาที, สร้างคำตอบ ~28 token/วินาที, ~33 วินาทีต่อช่วง 8 นาที |
| ปริมาณ token | ช่วงเสียงไทย 10 นาที = 5,564 token (รวมข้อความ prompt ~ราว 1,000 token) ประมาณ 450–550 token ต่อนาที → 1 ชั่วโมงราว 30,000 token จึงต้องแบ่งช่วงสรุป (ตัวเลขนี้เป็นการประมาณ ไม่ใช่ค่าที่วัดทั้งชั่วโมง) |

**การปรับปรุง prompt (ทดสอบกับบทสนทนาโทรศัพท์สังเคราะห์ที่ผู้ช่วยเขียนเอง ไม่ใช่เสียงจริง):**
- prompt แรก: รายการทุกหมวดว่างทั้งที่บทสนทนามีคำขอ/คำมั่นชัดเจน
- หลังเพิ่มบริบทผู้พูด + ตัวอย่าง 1 ชุด + ย้ายฟิลด์ overview ไปท้าย schema: ดึงได้ 5 คำขอ, 1 คำถาม, 3 คำมั่น, 5 รายละเอียด
- ทดสอบว่าตัวอย่างใน prompt ไม่รั่วเข้าเสียงบรรยาย: ไม่พบคำ "น้ำตาล" ในผลของเสียงบรรยาย
- ปัญหาเสียงบรรยาย: โมเดลวนซ้ำรายการเดิมจนชน token สูงสุด → แก้ด้วย `maxItems 8`, `maxLength`, repeat penalty 1.05, `dedupe`

**ตัวกันหลอน (verify):** ทุกรายการต้องมี "คำอ้างอิง" ที่ตรวจว่าอยู่ใน transcript จริง
- คำพูดจริง: ผ่านทุกรายการ (ทดสอบ 14/14 รายการสังเคราะห์) และข่าวช่อง 9 ผ่าน 11/11
- คำพูดปลอม ("ซื้อทุเรียนที่จตุจักร"): ถูกปฏิเสธ
- **ข้อจำกัด:** จับ "แต่งคำอ้างอิง" ได้ แต่จับ "จับคู่รายการกับคำพูดผิดบรรทัด" ไม่ได้ (พบ 1 กรณี: คำมั่นเรื่องขนมจีนอ้างคำพูด "ได้ครับ ผมจะเอามาให้" ซึ่งเป็นของเรื่องใบเสร็จ) และถอดเสียงผิดตั้งแต่ต้นก็ตรวจไม่ได้
**สไลด์:** แผนภาพ "รายการสรุป → คำอ้างอิง → ตรวจกับ transcript → ป้ายตรวจไม่พบ" และตัวอย่างหน้าเว็บ

## 5. ข้อจำกัดของการทดลอง (ควรบอกในสไลด์)

- เสียงทดสอบหลักเป็น**เสียงอ่านสะอาด (FLEURS)** ที่เอามาต่อกัน ไม่ใช่สายโทรศัพท์จริง ช่วงเงียบและเสียงรบกวนเป็นของที่สร้างขึ้น
- รันแบบละครั้งเดียว ความต่างน้อยกว่า ~0.5 จุด CER ถือว่าไม่ต่างกัน
- ชุด 3 ภาษาเล็กมาก (14–30 วินาที) และเป็นเสียงคนเดียว
- เฉลย FLEURS เป็นเลขอารบิก ทำให้ I ของ Typhoon สูงขึ้นเทียบกับ turbo
- ตัวชี้วัด "รอยตัดกลางประโยค" แยกไม่ออกระหว่างตัดกลางคำกับตัดตรงจังหวะหยุดในประโยค จึงตัดสินจาก CER และต้องฟังตรวจประกอบ
- ตัวคำนวณ CER รุ่นแรก (`score.py`) ตัดสระ/วรรณยุกต์ทิ้ง คำนวณใหม่ใน `metrics.ts` ด้วย normalize ที่ถูกต้อง ผลต่างจากเดิมไม่ถึง 0.2 จุด ข้อสรุปไม่เปลี่ยน
- ยังไม่ได้ทดสอบกับสายโทรศัพท์จริง และยังไม่ได้ทดสอบการให้ Qwen แก้คำถอดเสียง
